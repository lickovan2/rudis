# RUdis

Русский аналог Discord: серверы, текстовые и голосовые каналы, личные сообщения, друзья, файлы и реакции. Интерфейс полностью на русском. Есть веб-версия и десктоп-клиент для Windows.

## Что умеет

- **Серверы**: создание, иконка, приглашения по ссылке, роли «владелец / администратор / участник», исключение участников.
- **Текстовые каналы**: сообщения в реальном времени, ответы, редактирование и удаление, реакции, «печатает…», непрочитанные, упоминания `@логин`.
- **Разметка**: `**жирный**`, `*курсив*`, `__подчёркнутый__`, `~~зачёркнутый~~`, `||спойлер||`, `` `код` ``, блоки ```` ``` ````, `> цитаты`, ссылки.
- **Файлы**: вложения до 25 МБ (кнопка, вставка из буфера, перетаскивание), превью картинок, видео и аудио.
- **Голосовые каналы**: WebRTC, индикатор говорящего, выключение микрофона и звука, громкость каждого участника, выбор микрофона и динамиков.
- **Друзья и ЛС**: заявки по логину, статусы «в сети / не в сети», личные переписки, уведомления.
- **Десктоп**: Electron-клиент с выбором адреса сервера, счётчиком непрочитанных и доступом к микрофону.

## Запуск для разработки

Нужен Node.js 24+.

```bash
npm install
npm run dev        # сервер на :3001 + веб на http://localhost:5173
```

Откройте http://localhost:5173, зарегистрируйтесь, создайте сервер и позовите друга ссылкой-приглашением.

Десктоп-клиент в режиме разработки:

```bash
RUDIS_URL=http://localhost:5173 npm run desktop
```

## Продакшен-сборка

```bash
npm run build      # собирает web/dist
npm start          # сервер отдаёт API, WebSocket и собранный фронт на :3001
```

Портативный exe для Windows:

```bash
npm run dist -w desktop   # desktop/dist/RUdis-<версия>-portable.exe
```

При первом запуске клиент подключается к `https://gramanalyzer.xyz`. Адрес сервера меняется через меню «RUdis → Сменить сервер…».

## Продакшен: https://gramanalyzer.xyz

Развёрнуто на VPS рядом с другими проектами, изолированно:

| Что | Где |
| --- | --- |
| Код | `/opt/rudis/app` |
| Свой Node 24 (системный Node не трогаем) | `/opt/rudis/runtime/current` |
| База и файлы | `/opt/rudis/data` |
| Секреты (JWT, TURN) | `/opt/rudis/rudis.env` (600) |
| Сервис | `rudis.service` (systemd, `127.0.0.1:3050`, лимит памяти 400 МБ), лог `/var/log/rudis.log` |
| Резервные копии | `rudis-backup.timer` ежедневно сохраняет согласованную копию SQLite и вложения в `/opt/rudis/backups` на 14 дней |
| TURN | `coturn.service`, `85.209.129.34:3478`, relay-порты UDP 49160–49400 |
| nginx | vhost `gramanalyzer`: `/chart/` и `/health` → сервис графиков (8899), остальное → RUdis |

Обновление: собрать `web/dist`, упаковать `git archive` + `web/dist`, распаковать в `/opt/rudis/app`,
`npm ci --omit=dev -w server` (с `PATH=/opt/rudis/runtime/current/bin:$PATH`), `systemctl restart rudis`.
Данные принадлежат отдельному пользователю `rudis` и недоступны другим локальным пользователям.
Для защиты от отказа самого VPS копии из `/opt/rudis/backups` нужно дополнительно вывозить на другой хост.
На существующем VPS вход root по паролю через SSH отключён; вход по ключу сохранён.

При установке на новый VPS создайте системного пользователя `rudis`, передайте ему `/opt/rudis/data`
и задайте для каталога права `700`, а для файлов базы и вложений `600`. В `rudis.service`
укажите `User=rudis`, `Group=rudis` и `UMask=0077`. Установите
`deploy/rudis-backup.service` и `deploy/rudis-backup.timer` в `/etc/systemd/system/`,
затем выполните `systemctl daemon-reload` и `systemctl enable --now rudis-backup.timer`.

## Настройки сервера (переменные окружения)

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `3001` | Порт HTTP и WebSocket |
| `JWT_SECRET` | dev-значение | **Обязательно поменять в продакшене** |
| `DATA_DIR` | `./data` | База SQLite и загруженные файлы |
| `TURN_URL` | — | Свой TURN-сервер (coturn) для голоса через сложные NAT |
| `TURN_SECRET` | — | Общий секрет coturn (`use-auth-secret`): сервер выдаёт временные логины на сутки |
| `TURN_USER`, `TURN_PASS` | — | Постоянные логин и пароль TURN, если секрет не используется |
| `MAX_TOTAL_UPLOAD_BYTES` | 5 ГБ | Общий лимит загруженных файлов (отдельно 500 МБ на пользователя) |

## Голос: как устроен и ограничения

Голос работает по схеме P2P-mesh: каждый участник соединён с каждым напрямую, а сервер только пересылает сигналинг. Это не требует медиасервера и хорошо работает примерно до 6–8 человек в канале. Для больших каналов следующий шаг — SFU (LiveKit или mediasoup).

Для голоса между разными сетями нужен TURN-сервер, иначе часть пользователей за строгим NAT не соединится. Браузер пускает к микрофону только на `https://` или `localhost`, поэтому в продакшене нужен TLS (nginx + Let's Encrypt).
